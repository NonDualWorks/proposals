Three rules

  • One venueTalk in the Discussion until there's a PR, then only on the PR.
  • Votes adviseThe decider decides, and writes down why.
  • Keep the no'sDeclined proposals stay, so ideas don't return without new evidence.

Every proposal is tagged

  • WherePlane: developer interface, delivery, resources, monitoring, security
  • WhyPillar: makes delivery legible, trustworthy or answerable
  • How farMaturity: which aspect moves, e.g. Interfaces L1 → L2. Levels describe the team, so they live in the heatmap, not here.

Not everything needs this

  • ADRInternal decision, no user change. A short record next to the code.
  • LiteSmall and reversible. One page, 48 h comment period.
  • FullNew capability or a migration. The whole flow above.
